Markup to Revision

A reviewer marked up a 28-page price list with 70 sticky notes and needed two versions the same day. I directed the round and Claude did the edits, fixes and checks.

apartmentClient

In-house marketing (anonymized)

descriptionDeliverable

28-page price list, two versions

design_servicesRole

Production design & direction

auto_awesomeBuilt with

Claude · InDesign scripting

reportThe job

Seventy notes, two versions, one deadline

The markup changed 65 prices, the effective date and three tables, and added one product that only belonged in the launch version. Typing that by hand twice is slow, and one wrong price in a price list is the kind of mistake a customer finds first.

call_splitRoles

I kept the judgment, Claude took the repetition

I shared the request from the project board and the marked-up PDF, then steered.

  • check_circleI pointed it at the existing project, so this became a new round, not a new job.
  • check_circleI confirmed which PDF was the source of truth before anything changed.
  • check_circleClaude filed a written brief and the markup in the project's source folder.

codeEdits

One script instead of 65 hand edits

Claude matched every sticky note to its table row and wrote one layout-app script for both versions.

  • check_circleA price changed only where the old value matched exactly on the expected page.
  • check_circleAnything ambiguous was skipped and logged instead of guessed.
  • check_circleThe launch version was saved as a copy, then given its extra row.

buildFallout

Every edit broke something small

The log came back clean, but the pages didn't. Claude found and fixed each problem before I saw it.

  • check_circleThe new row overflowed its page, so the frame grew and the footnote moved down.
  • check_circleRegistered marks arrived garbled from a file-encoding mismatch.
  • check_circleDeleted rows reflowed a table, stranding a section header and a free-floating image.

imageAssets

A cutout to match the rest of the table

The new product's photo came with a drop shadow the other rows don't have. I asked for a clean version; Claude removed only the semi-transparent shadow layer and kept the product's edges intact. I placed the images and tightened the page myself, since that's a judgment call made by eye.

fact_checkVerification

The PDFs were checked against the markup, not the script

After export, Claude read the text back out of both PDFs and compared it with every note: each new price present, each old price gone, deleted rows absent, and the launch-only row in one version only. Then it looked at the pages that changed.

visibilityThe catch

The last fix came from knowing the job

The revision code on the back page still read R4. It wasn't in the markup, so no check against the markup could find it. I spotted it, Claude relabeled both files and re-exported, and the round shipped.

flagWhat's next

Things to improve

  • radio_button_uncheckedVersion label in the script. The revision code should change with the edits, not after export.
  • radio_button_uncheckedReflow checks by default. Any page that loses rows should get a look for stranded headers and floating images.
  • radio_button_uncheckedSafer script encoding. Scripts should escape special characters so symbols survive the trip into the layout app.
  • radio_button_uncheckedArchiving stays manual. Moving old rounds means deleting originals, so a person should keep doing it.
