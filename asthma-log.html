Asthma Log

With caregivers trading night shifts, the 2am question was always: when was the last asthma dose, and is another OK now? I designed and built a family web app that answers it at a glance, simple enough for the child to log doses too.

Asthma Log

reportThe problem

Three questions, asked half asleep

Every night came down to three questions: when was the last dose, is it too soon for another, and were both nebulizer treatments done today? The rescue inhaler needs four hours between doses and the nebulizer runs morning and night, so with two people sharing the job, sticky notes failed fast. At checkups the pediatrician adds a fourth: how often is the rescue inhaler used?

play_circleWalkthrough

A morning, start to finish

It's 7:45 and the morning nebulizer is due. Log it with a note, check it in History, add a new medication, then head back to Dosage, where its card is already waiting.

scheduleThe core pattern

The answer first, the form second

The app opens on a Next dose card for each medication, before any form. A spaced medicine like the rescue inhaler shows the earliest next dose, Tomorrow, 12:30am, with a Too soon or OK to give label and a countdown. A scheduled one like the twice-a-day controller shows today's status and the next slot: Completed, Tomorrow, Morning. No math.

touch_appLogging

Clear enough for a child to log a dose

Logging is three numbered steps, pick, check and save, so the child can do it alone without the app turning childish.

  • check_circleBig medicine buttons say if it's time: Due this morning, Wait until 12:30am
  • check_circleAmount and time fill in, the note hides behind Add a note, and Save names the medicine
  • check_circleDouble taps: Save locks, Undo appears, and a repeat within ten minutes asks first
  • check_circleOnly rescue or controller is asked, since that type drives the schedule and chart

bar_chartHistory

A week at a glance, ready for the doctor

History opens on a Last 7 days card with the week's totals and rescue and controller doses side by side per day, so a heavy rescue day stands out, which is what the pediatrician asks about. The dose list below shows Today and Yesterday, with Load more. Copy 30-day summary turns the log into plain text for a message or patient portal.

lockSharing

Anyone can look, only family can log

Anyone with the link sees the same live log, so a grandparent can check the last dose without calling. Logging, deleting and editing medications take a family password, entered once per phone, which also unlocks a floating Log dose button on every tab. The database's sign-in and security rules enforce it, so editing the page can't get around it.

tuneDetails

Built for 2am

Most doses get logged in a dark room by someone who just woke up.

  • check_circleA dark mode that won't light up the room, a white light mode, and a manual switch
  • check_circleSource Sans 3 for small-size legibility, with compact times like 12:30am
  • check_circleInstalls to the home screen and works offline, syncing once back online
  • check_circleA Last Dose line on every tab naming the latest medicine and how long ago

auto_awesomeProcess

Shipped in an evening, refined by real use

I set the direction and made the design calls, and Claude wrote the code. The first version went live in one evening. Real use shaped the rest: catching double taps, dropping inhaler and nebulizer labels, trimming History to two days, and rebuilding the form for the child. It's one HTML file on GitHub Pages with Firebase, free to run and easy to maintain.

Things to improve

  • radio_button_uncheckedReminders. The app shows when a dose is due but notifies no one, so an alert for the controller or an allowed rescue dose would close the loop.
  • radio_button_uncheckedWho gave it. One shared password means the log can't tell a parent's entry from the child's, which separate sign-ins would fix without extra steps.
  • radio_button_uncheckedReal schedules. Morning and night split at noon, so a 2am dose counts as morning, and per-medication windows like 6 to 10am would fit real use.
  • radio_button_uncheckedTest the fast path first. Double taps saved duplicate doses until a save lock, Undo and two-second cooldown fixed it, so next time rapid-tap testing comes before launch.
  • radio_button_uncheckedA report for the doctor. The 30-day summary is plain text, and a one-page chart of monthly rescue use would make checkups faster.
